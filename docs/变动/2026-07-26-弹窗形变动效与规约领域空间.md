## 一、弹窗定位重构：让位给动画

### 变动动机

要做形变动效，面板的 transform 必须归 motion 独占。而 `DialogContent` 原来靠 `-translate-x-1/2 -translate-y-1/2` 居中，tw-animate 的 `zoom-*` / `slide-*` 关键帧会**整个改写 transform**，起始帧丢掉那 `-50%` 偏移，弹窗就会从偏左上斜着飘到中间。

| 文件                         | 改动内容                                                                                                                                                                                        | 为什么                                                                                                                                                                                          |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/shared/ui/dialog.tsx`    | ① 定位改为 `fixed inset-0 m-auto h-fit`；类名抽成 `DIALOG_CONTENT_CLASS` 常量                                                                                                                     | `margin: auto` 居中不占用 transform，缩放和位移动画才是"纯"的。抽常量是因为下面要按开关拼接动画类                                                                                                  |
|                              | ② 进出场类抽成 `DIALOG_CONTENT_ANIMATION_CLASS`：淡入 + `zoom-95` + `slide-in-from-bottom-3`，`duration-200 ease-out`                                                                              | 原来只有 fade + zoom、`duration-100`，偏生硬；补上自下微升并放慢到 200ms                                                                                                                          |
|                              | ③ 新增 `animated` prop（默认 `true`）                                                                                                                                                            | 形变模式下面板动画由 motion 接管，**内置 CSS 进出场必须关掉**，两套动画叠一起会互相打架                                                                                                            |
|                              | ④ `DialogOverlay` 遮罩 `duration-100` → `duration-200 ease-out`                                                                                                                                  | 与面板同节奏，否则遮罩先亮完、面板还在飞                                                                                                                                                          |
| `src/shared/ui/command.tsx`   | `CommandDialog` 的 `top-1/3 translate-y-0` → `mt-[33vh] mb-auto`                                                                                                                                | **连带修改**：命令面板要贴在视口三分之一处，原写法依赖旧的 `top-1/2 + translate` 体系；改 `m-auto` 居中后，等效做法是把上外边距钉死、下外边距吃掉剩余空间                                            |

> 影响面：所有走 `DialogContent` 的弹窗（确认框、创建文件夹/标签、密钥、头像裁剪、提示词工作台）位置逻辑都换了实现，视觉结果不变。

## 二、卡片 ↔ 编辑弹窗形变动效

### 变动动机

提示词草稿/收录的编辑弹窗原来是"凭空淡入"，跟点击的那张卡片没有视觉关联。改成共享 `layoutId` 的形变后，面板从来源卡片的矩形补间到弹窗尺寸，关闭时收回原位。

### 核心机制（五个约束，都是踩出来的）

- **同一个 `layoutId` 必须两侧共用一条曲线**，否则去程回程手感不一致 → 抽到 `shared/lib/motion.ts`。
- **同一个 `layoutId` 不能同时存在两个元素**，会互相拉扯 → 弹窗打开时卡片那侧撤掉锚点（`isMorphing`）。
- **来源卡片形变期间要整张淡出**，否则飞行中的面板和原地不动的卡片凑成一组重影。
- **圆角必须写成 `style` 里的数值**，不能用 `rounded-*` 类名：motion 只有拿到数值才能在缩放过程中逐帧反向修正，类名圆角会被缩放拉长、四角发虚。
- **阴影不能挂在形变层**：`box-shadow` 不受 motion 的缩放修正，跟着缩放会糊成一片 → 阴影改挂在内容层，跟内容一起淡入。

### 文件清单

| 文件                                                                | 状态 | 改动内容                                                                                                                                             | 为什么                                                                                                                                                    |
| ------------------------------------------------------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/shared/lib/motion.ts`                                           | 新增 | `MORPH_TRANSITION`（spring / `duration: 0.26` / **`bounce: 0`**）、`MORPH_CONTENT_TRANSITION`（`duration: 0.16` + `delay = MORPH_DURATION`）、`MORPH_RADIUS`（card 8 / panel 12） | 三个值都必须两端对齐：曲线（`bounce` 给 0 是因为形变的是一整块面板，回弹会让四条边来回甩）、内容淡入时机（由飞行时长推出，改一个值两边一起走）、圆角数值（对齐 `rounded-lg` / `rounded-xl`） |

## 六、遗留 / 待确认

**领域空间前端未接（本批最大的缺口）**：

- `getRuleSpaces` / `createRuleSpace` 已导出但**无调用方**，`src` 下没有任何空间切换 UI。
- `getRules` 客户端（`src/entities/rule/api/get-rules.ts`）**没有透传 `spaceId`**，只拼了 `folderId` / `tagIds` / `q` / `offset`。所以 `listRulesDtoSchema.spaceId` 和 `GET /api/rules` 的空间过滤目前**从前端够不着**。
- `FolderCombobox` 同样没传 `spaceId`，`GET /api/folders` 的空间过滤也还没有调用方。
- 结论：后端已按"空间隔离"落库（新规则/新规约文件夹都会归到默认空间），但前端仍是"单空间"视角。要真正用上，下一步得做空间切换器 + 把 `spaceId` 串进列表查询与文件夹查询。

**文档与代码不一致**：

- `prisma/schema/rule.prisma` 的注释写规约文件夹用 `resourceType="ruleFolder"`，但 `FOLDERABLE_RESOURCE_KEYS` 里实际只有 `"rules"`，代码（`app/api/folders/route.ts` 的 `RULE_RESOURCE_TYPE`）按 `"rules"` 走。是 prisma 注释过期，建议改注释而不是改代码。

**其他**：

- `app/api/rules/spaces/route.ts` 只覆盖个人空间（`teamId: null`），团队空间等 `defaultWorkspace` 基础设施上线后再接（文件头注释已标注）。
- 空间目前只有列表和新建，**没有改名 / 删除 / 排序**接口；`sortOrder` 写入了但前端还没有拖拽排序。
- 形变动效依赖来源卡片存在。收录页无限滚动下，若正在编辑的卡片所在分页被卸载，形变会静默退化为普通展开——目前是可接受行为，不算 bug。
