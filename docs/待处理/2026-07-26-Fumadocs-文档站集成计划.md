# Fumadocs 文档站集成计划

## Context(背景与已确认决策)

用户要为 ai-spec 集成 Fumadocs 文档站。已确认两个关键决策:

1. **定位:对外产品文档**——面向 ai-spec 最终用户(产品介绍、使用指南、快捷键速查),不是开发文档。内容视角要用户化,不搬 FSD/架构解读这类开发向内容。产品叙事参考:两大卖点是「归纳 AI 知识 + 复用」(README 产品介绍质量不错,可作首页素材;快捷键体系刚落地,速查页可从 hotkeys.config.ts 整理)。
2. **内容范围:骨架 + 首批精选**——新建 `content/docs/` 内容目录,搭好导航结构,首批写入产品向的几篇种子页。原 `docs/` 保持不动作内部工作区。

## 宿主环境探索结论(已核实)

**路由与鉴权:**
- `/docs` 路由空闲;无 middleware.ts(Next 16 改名 proxy.ts,函数体空放行);鉴权是页面级 `await auth()`,`/docs` 天然公开,无需改 proxy/auth
- `app/layout.tsx` 是唯一根布局(薄层),html/body 在 `src/app/layouts/root-layout.tsx` 的 RootLayoutShell(async server component,`<html lang="zh-CN" data-theme={...} class含字体变量>`);Provider 链:RootThemeProvider(next-themes, attribute="class") → SessionProvider → ActiveThemeProvider → SwrProvider
- 按 app/AGENTS.md 规范:app/ 只做薄层,页面主体应放 `src/pages/docs/`
- 注意:`next.config.ts` 的 redirects 把 `/` 跳到 `/spec/personal`;auth 布局卸载时会把主题重置为 system(既有行为)

**样式与主题(两大坑):**
- Tailwind v4,入口 `src/app/styles/global.css`(@import "tailwindcss" + tw-animate-css + theme.css + code-theme.css,@plugin typography)
- 坑 1:`dark` variant 被重定义为 `&:is(.dark * )`(只匹配后代);坑 2:shadcn 变量不在 `:root`,嵌在 `[data-theme="base-vega"]` 及 `.dark` 组合选择器内,`@theme inline` 也嵌套其中(themes/base-vega.css:70-115)。Fumadocs 自带 CSS 假设 `:root` 变量与标准 dark:,需做变量映射层
- 明暗 = next-themes class;配色 = data-theme 属性(cookie SSR + ActiveThemeProvider)。fumadocs-ui 的 RootProvider 内置 next-themes,必须禁用其 theme provider 复用宿主的
- 代码高亮:宿主是 highlight.js + code-theme.css,Fumadocs 默认 Shiki——文档站作用域内用 Shiki,互不影响

**构建与工具链:**
- next.config.ts 是干净的纯对象(无任何 withXxx),直接包 createMDX 即可;Next 16.2.10(锁死)、React 19.2.4(锁死)、TS ^5、dev/build 默认 turbopack
- scripts 无 postinstall;fumadocs-mdx 的 `.source` 生成目录需要:.gitignore(先例 /src/shared/db/generator)+ biome override 关检查(先例 db/generator 全关)+ 可能需要 postinstall script
- tsconfig:paths 仅 `@/*` → `./src/*`;`exclude: ["docs"]`(现有 docs 被 TS 排除——新内容根用 content/ 避开);include 无 .mdx
- biome:`files.includes: ["**", "!docs"]`;dprint 管 .md(不含 .mdx,需决定是否纳入)
- markdown 现有运行时渲染链(react-markdown + remarkGfm + rehype-slug/external-links/highlight)与 Fumadocs 构建时 MDX 并存,互不复用

## Fumadocs 调研结论(已核实)

**版本与兼容:**
- fumadocs-ui / fumadocs-core **16.12.1** + fumadocs-mdx **15.2.0**;v16 的 peerDeps 强制 next 16.x + react ^19.2 —— 宿主 16.2.10/19.2.4 精确命中
- Node v24 满足(Turbopack 下 require(esm) 问题需 Node 22+)
- 装包:`pnpm add fumadocs-ui fumadocs-core fumadocs-mdx @orama/tokenizers` + `-D @types/mdx`
- v16 注意:provider 入口必须用 `fumadocs-ui/provider/next`

**集成骨架:**
- `source.config.ts`(根):defineDocs({dir:'content/docs'}) + defineConfig({postprocess:{includeProcessedMarkdown:true}})
- `next.config.ts` 包 createMDX();**ESM-only 是最大不确定点**,失败回退 .mjs
- tsconfig paths 加 `"collections/*": ["./.source/*"]`;package.json 加 `"postinstall": "fumadocs-mdx"`;`.source/` 进 .gitignore(biome 走 vcs.useIgnoreFile 自动跳过;TS glob 不匹配点开头目录,不会进编译单元)
- Next 16 typed routes(`PageProps<'/docs/[[...slug]]'>`):首次 typecheck 前必须先跑一次 dev/build

**样式方案(关键裁决):**
- 绝不把 fumadocs CSS 放进 global.css(preset 的 @layer base 会覆写全站 body/border 色)
- 新建独立 docs.css:`@import 'fumadocs-ui/css/shadcn.css'` + `preset.css`,只在 app/docs/layout.tsx import
- shadcn.css 是纯变量映射(--color-fd-* → var(--background)...),宿主 shadcn 变量挂 [data-theme] 于 html(:root)可解析 → 文档站自动跟随 base-vega/domm64 双主题
- 残留验证点:preset 内置 typography 与宿主 @plugin typography 的 prose 冲突;@variant dark 语义差异(fumadocs 匹配 .dark 自身,宿主只匹配后代)
- RootProvider 必须 `theme={{ enabled: false }}`(复用宿主 next-themes,.dark 选择器开箱即通),放 app/docs/layout.tsx(只影响 /docs)

**中文支持:**
- 搜索:默认 Orama 分词对中文失效,必须 `@orama/tokenizers/mandarin` 的 createTokenizer() + `search:{threshold:0, tolerance:0}`;纯中文站顶层传即可无需 localeMap
- 文件名:一律英文 kebab-case + 中文 frontmatter title(中文文件名会 percent-encode 进 URL)
- dprint 只管 .md 不管 .mdx;建议显式排除 content/ 防破坏 JSX

**AI-native(可选):** llms.txt / llms-full.txt / 每页 .md / Accept 协商均官方内置,靠 postprocess.includeProcessedMarkdown + getText('processed')

## 方案设计

### FSD 裁决:文档站内聚为 `src/pages/docs/` 单一 slice

所有基础设施(loader、布局、MDX 组件、样式、搜索装配)放 `src/pages/docs/`,根 `app/docs/**` 与 `app/api/search/` 薄层委托(同 `app/spec/(dashboard)/layout.tsx` → DashboardLayout 的既有模式)。不放 `src/app/`(单路由私有物不该提升为全局装配)、不放 shared(绑定具体业务内容)。

### 文件清单

**新建 slice(src/pages/docs/):**
- `index.ts` — 公有 API:DocsSiteLayout、DocsSlugPage、generateDocsStaticParams、generateDocsMetadata、docsSearch
- `model/source.ts` — loader({ baseUrl: "/docs", source: docs.toFumadocsSource() });docs 从 `.source` 生成物导入(具体模块名以首次生成实测为准)
- `config/layout-options.tsx` — baseOptions:标题「Prompt Shelf 文档」、links 加「返回应用 → /spec/personal」
- `ui/docs.css` — 仅两行:@import 'fumadocs-ui/css/shadcn.css' + 'preset.css';文件头 `!` 注释「严禁并入 global.css」
- `ui/layout.tsx` — DocsSiteLayout:import docs.css → RootProvider theme={{enabled:false}} → DocsLayout tree={source.pageTree}
- `ui/page.tsx` — DocsSlugPage + generateDocsStaticParams + generateDocsMetadata
- `ui/mdx-components.tsx` — getMDXComponents(defaultMdxComponents 扩展点)
- `api/search.ts` — createFromSource(source, { components:{tokenizer:createTokenizer()}, search:{threshold:0,tolerance:0} })(@orama/tokenizers/mandarin)

**新建 app 薄层:** `app/docs/layout.tsx`、`app/docs/[[...slug]]/page.tsx`(PageProps<'/docs/[[...slug]]'>,禁 as)、`app/api/search/route.ts`(export const GET = docsSearch.GET)

**新建根配置:** `source.config.ts`(defineDocs dir 'content/docs' + defineConfig postprocess.includeProcessedMarkdown)

**修改 5 个:** next.config.ts(尾部 withMDX 包裹)、package.json(4 个 deps + @types/mdx + postinstall "fumadocs-mdx")、tsconfig.json(paths 加 collections/*)、.gitignore(.source/)、dprint.jsonc(excludes 加 content/**)

### 内容结构(6 页种子,英文文件名 + 中文 frontmatter title)

```
content/docs/
├── meta.json          # pages: ["index","quickstart","---核心功能---","...guides","---参考---","hotkeys"]
├── index.mdx          # 认识 Prompt Shelf(README 产品介绍改写:两大卖点、痛点对照、三步理念、功能导览 Cards)
├── quickstart.mdx     # 快速上手(用户三分钟动线:登录→记草稿(C)→整理成收录→一键复制→⌘K)
├── guides/
│   ├── meta.json      # pages: ["records","drafts","rules"]
│   ├── records.mdx    # 收录库(创建/⌘↵ 保存/复制统计/版本回滚/搜索筛选)
│   ├── drafts.mdx     # 草稿箱(便签式捕获、与收录分工、升级动线)
│   └── rules.mdx      # 规约库与 AGENTS.md(三层结构、引用而非复制、装配动线;源自 docs/项目设计/业务设计/规约库.md)
└── hotkeys.mdx        # 快捷键速查(从 hotkeys.config.ts + editor.ts 的 shortcut token 逐条核实,⌘/Ctrl 双列,按作用域分组)
```

### 实施步骤(两道闸门)

1. 装包:pnpm add fumadocs-ui fumadocs-core fumadocs-mdx @orama/tokenizers + -D @types/mdx
2. 根配置:source.config.ts → postinstall → .gitignore → tsconfig paths → dprint excludes → 最后 next.config.ts
3. **闸门 1(ESM 判定)**:放最小 index.mdx + meta.json 跑 pnpm dev;起得来则 .ts 配置可用,报 ERR_REQUIRE_ESM 类错误则回退 next.config.mjs;`ls .source` 确认生成物模块名
4. slice 基础设施(依赖 .source 存在):model/source.ts → config → ui/mdx-components → ui/docs.css → ui/layout → ui/page → api/search → index.ts
5. app 薄层三文件
6. **闸门 2(typed routes)**:跑 dev 访问 /docs(或 next typegen)生成 .next/types,之后才能 pnpm typecheck
7. 其余 5 页内容 + guides/meta.json
8. 验证清单

### 风险预案

- **ESM 失败** → next.config.mjs(现有配置平移,JSDoc 保类型)
- **fumadocs 组件无样式** → docs.css 升级完整编译入口:@import "tailwindcss" source(none) + @source 指向 fumadocs-ui/dist + @custom-variant dark 与宿主一致
- **prose 冲突**(宿主 prose 用于 markdown-preview.tsx:21、version-page.tsx:192,206)→ 先验证后处理:/docs 与收录详情/版本页互相导航检查排版;污染则 preset 加 layer(fumadocs) 压层级
- **dark 语义差异** → 同预案 2,docs.css 声明宿主版 @custom-variant dark
- collections 导入名/RootProvider 入口(fumadocs-ui/provider/next 优先)以装包实测为准

### 验证清单

dev 手测:侧边栏中文导航与分隔符、TOC/翻页;⌘K 搜索中文「草稿/快捷键/规约」出结果(/docs 无 kbar,不冲突);/spec 切暗色/切主题后进 /docs 均跟随;/docs ↔ 收录详情/版本页互导无样式污染;移动端抽屉;URL 全英文。
静态检查:typecheck 0 error(闸门 2 后)、lint:ci 通过、format:md 不碰 content/、build 成功。
