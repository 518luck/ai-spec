## 规约库是什么

规约库是你为 AI 编写约束规则的地方。每条规约都是一个「原子」：React 的组件风格、Go 的错误处理、命名规则……一条规约只讲一件事，可短可长。

这些原子规则本身不直接使用，它们的去处是 **AGENTS.md**——AI 编码工具读取的项目规范文件。你可以这样理解两者的关系：

- **规约库** = 存放原子规则的「零件库」
- **AGENTS.md** = 把零件装配成机器的「车间」

零件在库里只放一份，车间按需取用、组合成型。

<Callout title="和收录库的区别" type="info">
  收录库里的提示词是「一次性指令」，复制进聊天框、用完即弃；规约库里的规则是「长期约束」，被 AGENTS.md 引用后持续生效。前者去聊天框，后者去项目规范。
</Callout>

## 三层组织：空间、文件夹、标签

规约多了之后，靠一层文件夹是理不清的。规约库用三层结构来组织：

| 层级 | 作用 | 特点 |
| --- | --- | --- |
| **领域空间** | 隔离不同的技术领域 | 顶层「车间」，彼此完全独立 |
| **文件夹** | 空间内的分类 | 只有一层，不嵌套 |
| **标签** | 空间内的横向检索 | 可以贯穿文件夹，聚合同一主题 |

- **领域空间**是物理隔离的：代码规约、创作规约、智能体规约各住各的空间，一条 React 规则永远待在代码空间，不会漂到别处。
- **文件夹**解决空间内的分类，比如代码空间下分 react、go、typescript。一层就够，嵌套只会增加心智负担。
- **标签**解决「同一主题散落在多个文件夹」的问题：给不同文件夹里的规则打上同一个标签，一次筛出全部。

<Callout title="标签出不了空间" type="warn">
  标签只在当前领域空间内生效，无法跨空间聚合规则。这是刻意设计：找得到，但归属不变，空间之间始终干净隔离。
</Callout>

## 引用而非复制

规约库最核心的机制是：**AGENTS.md 引用规则，而不是复制规则。**

- 每条规则在规约库里只有一份。
- AGENTS.md 通过引用，把规则挂载进自己的章节结构。
- 同一条规则可以被多个 AGENTS.md 同时引用。
- 规则修改后，所有引用它的 AGENTS.md 自动更新——改一处，处处生效。

这意味着你维护的永远是「唯一事实来源」：团队约定升级了，只需要改规约库里那一条，不用去每个项目的规范文件里逐个翻找。

<Callout title="删除前请留意引用" type="warn">
  删除规则时如果它已被 AGENTS.md 引用，引用处会随之失效。因此删除操作需要手动键入确认，防止误删。
</Callout>

## 从规则到 AGENTS.md

一条完整的装配动线是这样的：

1. **写规则**：在规约库点「新增规约」（或按 `C`）进入编辑页。用 Markdown 写正文，名称会自动取正文的第一行，也可以手动修改；顺手选好文件夹、打上标签。
2. **攒零件**：日常在使用 AI 的过程中，把反复要交代的约束一条条沉淀进来，按空间和文件夹归位。
3. **进车间**：打开 AGENTS.md 页面（命令面板 `⌘K` / `Ctrl+K`，或按 `G` `A`），按项目组织你的规范文档。
4. **装配**：在 AGENTS.md 的章节树中引用规约库里的规则，把原子零件组合成一份系统化的项目规范。
5. **交给 AI**：装配好的 AGENTS.md 就是你的 AI 编码工具读取的规范，规则更新会自动同步到引用处。

## 浏览、筛选与快捷键

规约库首页提供两种视图，右上角一键切换：

- **表格视图**（默认）：信息密度高，适合快速扫视和批量整理，标签一目了然。
- **卡片视图**：更直观地浏览每条规则的内容。

筛选从上到下逐层收窄：

- 顶部工具栏先选**领域空间**，再选空间下的**文件夹**；
- 列表上方可按**标签**过滤，跨文件夹聚合同主题规则；
- 搜索框支持按标题或正文搜索，按 `/` 直接聚焦。

常用快捷键：

| 快捷键 | 作用 |
| --- | --- |
| `C` | 新建规约 |
| `/` | 聚焦搜索框 |
| `⌘K` / `Ctrl+K` | 打开命令面板 |
| `G` `G` | 跳转到规约库 |
| `G` `A` | 跳转到 AGENTS.md |

完整键位见[快捷键参考](/docs/hotkeys)。
