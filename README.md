# Prompt Shelf

一个提示词管理平台，帮助用户高效组织、存储和使用 AI 提示词。

## 解决的问题

在使用 AI 的过程中，用户经常面临以下痛点：

### 1. 提示词散落各处，难以快速找到

用户在不同场景下积累的提示词（如角色扮演、代码重构、文案生成等）通常分散在笔记软件、聊天记录、文档等各处，需要时往往记不清放在哪里，导致重复编写相似的提示词。

### 2. 缺乏版本控制，无法追踪演变

提示词在使用过程中会不断优化迭代，但传统方式无法记录每次修改的内容和原因，导致好的版本被覆盖后难以恢复，也无法回溯优化过程。

### 3. 团队协作困难，提示词无法共享

团队成员各自积累的优质提示词无法有效共享，新人入职需要重新摸索，团队无法形成统一的提示词资产库。

### 4. 复制粘贴流程繁琐

使用提示词时需要经历"打开文档 → 找到提示词 → 选中复制 → 切换到 AI 界面 → 粘贴"的多步操作，打断工作流。

## 核心设计理念

**"找到 → 复制 → 粘贴，三步之内必须完成。"**

Prompt Shelf 的所有设计都围绕这条最短路径展开，让用户能在 3 秒内完成从查找提示词到使用的全过程。

## 主要功能

### 草稿与收录双轨管理

- **草稿**：便签式快速捕获，无需想标题，即记即用
- **收录**：正式归档，支持标题、描述、标签、版本控制

### 一键复制

列表页的每个提示词卡片都直接显示复制按钮，点击即复制全文到剪贴板，无需进入详情页。

### 版本历史

每次编辑自动记录版本，支持查看历史记录和回滚到任意版本。

### 团队协作

- 支持创建团队空间，共享提示词资产
- 团队成员可贡献、收藏、使用团队提示词

### 标签与分类

通过标签系统对提示词进行分类，支持快速筛选和搜索。

### 使用统计

记录每个提示词的复制次数和使用频率，支持按热度排序。

## 技术栈

- **前端**：Next.js App Router、React 19、Tailwind CSS、shadcn/ui
- **后端**：Next.js API Routes、Prisma ORM
- **数据库**：PostgreSQL
- **认证**：NextAuth.js
- **部署**：Docker Compose

## AI 规约模块信息架构

> 本节记录「AI 规约」模块（AGENTS.md / Skills / Agents / Plugins / 规约库）的信息架构决策。详细的领域认知见 `.trellis/spec/big-question/claude-code-config-hierarchy.md`。

### 核心依赖链

```
规约(Rule)        ← 原子化的单条约定，用户收集拼凑
   ↓ 拼凑组合进
AGENTS.md         ← 项目级文档，200 行限制 → 单项目多份
   ↓ 绑定到
项目(Project)     ← 真实代码仓库
```

### 决策：以「项目」为中枢

用户主操作路径：

```
侧边栏: 项目(一级)
  └ 进项目 → 看这个项目的 AGENTS.md → 编辑某份 → 从规约库挑规约拼进去
```

用户心智：「我在管 ai-spec 这个项目，它的 AGENTS.md 需要补充，我去规约库找几条拼进来。」

理由：AGENTS.md 一般绑定到项目、很少通用；规约的终态归宿是拼进 AGENTS.md。因此用户的终态目标总是「某个项目的 AGENTS.md」，项目是天然的入口枢纽，规约库作为素材库从项目内调用。

### 侧边栏「AI 规约」分组结构

四项平级，各有独立管理界面：

| 入口 | 管理对象 | 性质 |
| --- | --- | --- |
| **项目** | 真实代码仓库 → 项目内多份 AGENTS.md | 容器，组装中枢 |
| **规约库** | 原子化规约（全局独立素材） | 独立资源，通过「拼进 AGENTS.md」动作连接项目 |
| **Skills** | 独立创作单元（高频编辑） | 独立资源，可个人全局或项目级 |
| **Agents** | 独立创作单元（高频编辑） | 独立资源，可个人全局或项目级 |
| **Plugins** | 打包分发的扩展包 | 低频组合发布产物 |

> Skills/Agents 是独立创作单元（高频），Plugin 是打包产物（低频）。四者平级合理——菜单按「用户日常操作对象」组织，不按「代码包含关系」组织。

### 个人空间侧边栏目录分配

两个分组：项目拎到分组 1 与规约库并列（组装中枢地位凸显），Skills/Agents/Plugins 独立成「资源」分组：

```
个人空间

├─ 内容             ← 分组 1（无标题）
│   ├ Prompt
│   │   ├ 收录
│   │   └ 草稿
│   ├ 规约库         ← 原子素材库
│   └ 项目          ← 组装中枢，和规约库并列
│       └ AGENTS.md（项目内文档，不独立成菜单项）
│
└─ 资源             ← 原"AI 配置"改名
    ├ Skills
    ├ Agents
    └ Plugins
```

- 项目拎到分组 1：凸显组装中枢地位，和规约库对等
- AGENTS.md 收进项目内：点项目 → 看项目内多份 AGENTS.md
- 资源分组：Skills/Agents/Plugins 都是用户创作/拥有的资源，「资源」比「配置」准确

### 规约 → AGENTS.md 的引用机制

**版本化引用（固定版本 + 可选升级）**：规约拼进 AGENTS.md 时引用固定版本，规约后续更新不自动传播；用户可选升级到新版本。

```
规约 v1 ──引用(固定 v1)──→ AGENTS.md A（项目 X）
规约 v1 ──引用(固定 v1)──→ AGENTS.md B（项目 Y）
规约 v2（更新后）──可选升级──→ AGENTS.md B 主动升到 v2
```

兼顾三个矛盾需求：复用（引用不复制）、稳定（固定版本不被污染）、迭代（可选升级）。本质是依赖管理经典模式，规约即「文档的依赖项」，基础设施由 `RuleVersion` 模型支撑。

**AGENTS.md 中间层保留**：它是「规约集合 → 真实仓库文件」的物化形态。规约是原子素材，AGENTS.md 是组装成品，项目是成品归属。去掉它规约就退化成散乱标签，无法落地成 `.md` 文件。

### 组装与升级入口：双向

| 动作 | 入口 A | 入口 B |
| --- | --- | --- |
| 拼规约进 AGENTS.md | 编辑器内「插入规约」 | 规约详情「应用到 AGENTS.md」 |
| 规约升级提示 | 编辑器标「v1→v2 可升级」 | 规约详情「被 N 份引用，M 份可升级」 |

两个入口服务两种出发心智，互为补充，最终指向同一底层操作。
